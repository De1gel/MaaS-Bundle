# 边界 assignment 切换

普通 tie 直接遵循 optimistic rule，切换到同一菜单上利润更高的 assignment，
继续区域优化。代码不再强制把已选中的高 margin 响应切到低 margin 一侧。
当区域 assignment 已经一致时，才对当前菜单的 double-tie 替代项进行额外求解。

同点/异点的返回判定本身不依赖 double tie；double tie 只用于选取额外的邻区。
入口仍为 `find_assignment_consistent_menu` / `solve_primal`。成本 tie 与选择可行性从
初值起共享有效阈值（默认 `1e-7`）；margin 搜索和最终诊断共享 `margin_tolerance`
（默认 `1e-9`），独立于总利润容差。详见[数值容差](numerical_tolerances.md)。

## 当前点决定是否继续

1. 在 A 中完成区域 NLP、约束生成和 full separation，得到菜单 x。
2. optimistic response 改变时，以 x 进入对应区域继续优化。若响应已经一致，
   保存 x，并逐个求解尚未检查的 double-tie 邻区；不枚举普通 tie 的递归分支。
3. 邻区 B 返回不同菜单 y：在利润不下降的前提下接受新菜单，清空旧点的检查记录，
   重新计算 optimistic response。即使利润相等，也在新点继续。
   如果 response 返回 A，必须从 y 优化 A；如果 response 仍为 B，B 已在 y 完成求解。
4. 邻区求解仍在 x：A 已在 x 完成区域求解，B 也在 x 完成检查，结束这次往返。
   有其他待检查邻区则继续；没有则返回 `CONSISTENT`，设置 `boundary_search_complete=True`。

assignment 标签相同、利润相同，都不能单独触发第 4 步。
即使启用 `stop_on_assignment_revisit`，异点或利润改善的重访仍继续优化；该选项仅对
未确认、无实质改善的同菜单重访保留诊断退出。同一 assignment 的异点返回
属于第 3 步；不沿用旧菜单处的区域结论。

## 数值上的同点判定

完整菜单包含所有价格和额度。对每个分量要求：

\[
|y_j-x_j|\le a+r\max(|x_j|,|y_j|).
\]

价格分量的 `a=boundary_tolerance`，额度分量的 `a=allowance_boundary_tolerance`，
两者分别配置，默认均为 `1e-7`；`r=boundary_relative_tolerance`，默认 `1e-6`。
比较是对称的，绝对误差与相对误差共同适应菜单的尺度。
此外，邻区目标相对 entry objective 的变化、真实 optimistic 利润相对保留点的变化，
都须在 `profit_tolerance`（默认 `1e-9`）内。

坐标接近只是复用原点的候选条件。若求解器返回菜单与 x 不完全相等，代码在**实际保留点 x**
重新检查 B 的 full separation、价格/非负约束及一阶 KKT；通过后才将该邻区记为完成。
不通过则按新点继续优化，或在利润下降时报告失败。完全相同的菜单复用该区域刚完成的检查。

浮点级利润变化不会单独清空同点检查记录。例如 `6e-12` 不超过默认利润容差。
但等利润、坐标明显不同的结果仍会进入新点搜索。

## 利润保护与结果

外部初值必须严格正利润。已接受菜单利润不下降；数值近点被确认时保留原菜单，
不以略低利润的数值近点覆盖它。失败或达到迭代上限时保留 incumbent，报告未完成。

- `boundary_origin`：本次邻区试探所对应的原区域记录编号。
- `boundary_returned`：是否已在同一保留菜单完成双方的区域检查。
- `accepted`：是否接受当前求解得到的菜单。同点复用会保留原菜单。
- `terminal_iteration`：支持最终保留菜单的区域记录，不一定是最后一次邻区求解。
- `boundary_search_complete`：当前点的数值边界检查是否完成。

现有区域 adapter 检查可行性和一阶 KKT；同点复核采用相同标准，不将其升级成独立二阶证书。
