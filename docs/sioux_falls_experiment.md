# Sioux Falls 五模式重叠网络实验

配置版本：`sioux-falls-monthly-usd-overlapping-five-mode-v3`。
物理网络为 24 个节点、76 条有向路段；528 个正流量 OD，每个 OD 两类旅客，共 1056 类。
五种交通方式可以在同一物理路段上运行，不再按容量瓜分路段。
默认在每条物理路段上提供全部五种方式，共 380 条方式弧；节点允许无额外惩罚的方式转换。
这是合成多模式扩展，方式覆盖、速度和经济参数均不是 Sioux Falls 的实测服务数据。

## 参数与单位

模式顺序固定为 `(bus, metro, bike, ride_hailing, car_sharing)`。

| 模式 | 原路段时间乘数 | PAYG 费率 | 单位额度供给成本 |
| --- | ---: | ---: | ---: |
| bus | 1.50 | 0.30 | 0.05 |
| metro | 1.00 | 0.60 | 0.08 |
| bike | 2.50 | 0.10 | 0.02 |
| ride_hailing | 0.65 | 1.20 | 0.15 |
| car_sharing | 0.85 | 0.90 | 0.10 |

源自由流时间先乘 0.6，从 0.01 小时换算为分钟，再乘上表的方式时间系数。
费率和供给成本单位均为 USD/方式路段通行次。一单位额度支付一次对应方式的路段通行，
不是一次完整 OD 出行或一次上车。路段时间固定，不随流量变化。
源容量保留为数据属性，不用于模式划分、供给约束或拥堵计算。

旅客两类权重为 0.45/0.55，时间价值为 0.18/0.32 USD/分钟。
两类方式偏好成本分别为 `(0.02, 0.04, 0.06, 0.08, 0.10)` 和
`(0.08, 0.065, 0.05, 0.04, 0.03)`，单位 USD/方式路段通行次。
频次为 `Uniform(8,20)` 和 `Triangular(20,32,44)` 次/人·月。
类型权重按 OD 源流量的相对份额归一化，不将源表合计 360600 当作实际月度人数。
利润单位为 USD/人·月，不乘 360600。

| 选项 | 月费（USD/人·月） | 五维额度（方式路段次/人·月） |
| --- | ---: | --- |
| PAYG | 0 | (0, 0, 0, 0, 0) |
| 套餐 1 | 20 | (16, 16, 4, 6, 6) |
| 套餐 2 | 40 | (40, 40, 12, 18, 18) |

两个收费套餐共 12 个连续变量（2 个价格、10 个额度）。价格有序、额度非负；
不设价格和额度上界，不强制两个套餐的额度有序。供给成本为五维额度的线性成本。
参数集中在 [sioux_falls_config.py](../src/maas_bundle/examples/sioux_falls_config.py)。

## 完整极点预处理与保存

并行方式弧会产生大量多模式路径，因此不显式枚举所有路径组合。
[network.py](../src/maas_bundle/oracle/network.py) 从有效路径不等式构造外近似，
枚举当前对偶多面体的全部极点，在每个极点调用最短路分离，再加入违反的路径约束。
当所有极点均通过分离时，每个路径的线性不等式在整个凸包上成立，外近似等于完整对偶可行域。
完整性验收容差为 `1e-9`；不设路径数或分离轮数上限。

```bash
maas-bundle preprocess sioux-falls \
  --output results/sioux_falls_five_modes/dual_vertices.npz
```

每个 OD/旅客类型保存一个完整六维极点集合 `(pi, omega_1, ..., omega_5)`，
三个套餐共享它。每 25 个 OD 原子写入一次检查点；相同配置再次运行可继续未完成部分。
压缩 NPZ 同时保存配置和几何指纹，以 `allow_pickle=False` 读取。
几何指纹包含路网、方式时间、时间价值、方式偏好和 PAYG 费率；不包含菜单或频次分布。
不同几何的缓存、缺少所需 OD 的缓存会报错，不能静默代用。

本次已保存全部 **1056 个集合、285910 个极点**，每集合 **96–914 个极点**。
预处理约 **57.40 秒**；独立新进程加载并构造完整问题约 **0.05 秒**。
机器相关耗时仅作为本次运行记录。
[预处理摘要](../results/sioux_falls_five_modes/preprocessing_summary.json)。

### 当前探索模式（2026-10-19）

五模式单次和多初值入口现在默认 `DEFAULT_SIOUX_FALLS_SETTINGS.check_kkt=False`。
通用 `ScipyRegionalSolver` 仍默认严格模式，其他算例的策略不随之改变。

探索模式跳过独立 NNLS/KKT 计算，以及对原生 `optimality` 的额外阈值验收；
使用求解器原生 `success`，同时保留区域可行性、价格顺序、全旅客约束分离、
真实利润和 assignment 检查。近点复核与微小利润损失保护也不会重新触发 KKT 计算。
记录中 `kkt_checked=false`，KKT 残差与通过状态为 `null`，不声称驻点验收通过。

2026-10-19 的试跑脚本启用探索模式、SLSQP 重启与 trust-constr 回退，写入新文件
`results/sioux_falls_five_modes/design_exploratory.json`；原有严格试跑记录保留。
`--strict-kkt` 可重新启用严格检查，`--no-recovery` 可禁用恢复链。
原生 `success`、退出码及退出原因现在随 NLP 指标记录。
策略修改后的探索模式实测见下一节。

### 受限估值与缓存优化（2026-10-19）

受限 NLP 现在仅计算当前关键约束涉及的旅客，使用显式行映射保持原旅客编号。
`BundleDesignProblem` 按旅客/套餐缓存最近一次额度对应的精确 `G` 和 `E[omega]`，
不对额度做舍入。只改价格时可直接复用；PAYG 的零额度估值在同一个问题实例内持续复用。
每个旅客/套餐最多保存一项，缓存大小有界。全量 separation 与真实 assignment 重算仍覆盖全部旅客。
自定义合成 problem 的全表估值实现保持兼容。

在初始 32 条关键约束涉及的 32 类旅客上，PAYG 已缓存、两个收费套餐额度改变时：

| 单次计算 | 原全量实现 | 当前受限实现 |
| --- | ---: | ---: |
| 下层估值调用 | 3168 | 64 |
| 扫描极点行数 | 857730 | 14216 |
| 估值/约束回调耗时 | 约 0.259 秒 | 约 0.00505 秒 |

只改价格的约束回调不调用下层 oracle，实测约 0.000054 秒。
完整 separation 在额度变化时仍计算全部旅客的两个收费套餐，约 0.189 秒。
这些是本次机器上的测量值，不设为测试通过阈值。

## SLSQP 恢复更新（2026-10-20）

当前五模式默认最多四次 SLSQP 重试，即首次求解加重试最多五次；重试时修复可行性，
后续起点做小扰动，最后一次使用数值约束 Jacobian。默认不再切换 trust-constr，
必须显式传入 `--solver-fallback` 才允许跨求解器回退。
`--slsqp-restarts` 控制额外内层尝试数，`--no-numerical-constraint-recovery`
可关闭最后一次数值 Jacobian 重试。

内层重试仍失败时，预算实验脚本从所有已估值菜单中利润最高的可行菜单重新计算
assignment，再次进入区域搜索。默认最多三次搜索重启（`--search-restarts`），共享
原总时间预算；`--no-recovery` 关闭两层恢复。库函数仍保留明确的失败返回状态，
实验驱动层负责继续搜索，不把失败试探作为已收敛解。

原 100 初值中失败的起点 78、81、85 已单独复跑，保持原 seed、极点缓存、2000 次
NLP 迭代上限和每阶段 30 区域上限，总预算设为每起点 180 秒。三者均在 120 秒内完成，
最终人均月利润分别为 14.200517、16.761017、15.323381，耗时 70.336、28.093、28.055 秒。
78、81 各需要一次搜索重启，85 由内层重试恢复；全程仅用 SLSQP。
独立重算最终菜单与最好已观察菜单的利润均一致。原 100 初值统计未覆盖或改写。
