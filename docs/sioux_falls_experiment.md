# Sioux Falls 月度实验配置

配置版本：`sioux-falls-monthly-usd-v1`。参数集中在
[sioux_falls_config.py](../src/maas_bundle/examples/sioux_falls_config.py)，
单次和多初值入口使用同一配置。命令行 JSON 的 `experiment` 字段记录实际默认参数、
单位、模式顺序及版本。经济参数是合成设定，不是 Sioux Falls 的实测价格或调查估计。

## 单位与网络

| 量 | 单位与含义 |
| --- | --- |
| 套餐周期 | 月；所有价格、额度和出行频次针对同一个月 |
| 路段时间、路径时间 | 分钟；路径时间为路段时间之和 |
| 时间价值 | USD/人·分钟 |
| 套餐价格 | USD/人·月 |
| 出行频次 \(\mu_i\) | 单向 OD 出行次数/人·月，连续需求近似 |
| 方式使用矩阵 \(N_{mr}\) | 每次 OD 出行在路径 r 上经过的模式 m 路段数 |
| 套餐额度 \(\varepsilon_{bm}\) | 模式 m 路段通行次数/人·月 |
| PAYG 费率、供给成本系数 | USD/路段通行次 |
| 模式偏好成本 | USD/路段通行次，为广义成本而非额外收费 |
| 期望总广义成本、平台归一化利润 | USD/人·月 |
| 类型权重 \(w_i\) | 无量纲，归一化人口份额的合成代理 |

一次经过一条对应模式的有向路段消耗一单位额度。这不是一次上车、一次完整 OD 出行、
一公里或一分钟；不同路径的一次 OD 出行会消耗不同数量的两种额度。

24 个节点、76 条有向路段、528 个正流量 OD、每 OD 两类旅客，共 1056 个类型。
采用全部简单路径构造对偶约束，全部极点预处理并缓存，后续菜单求值不重新求解下层 LP。

[TNTP 源说明](https://github.com/bstabler/TransportationNetworks/blob/master/SiouxFalls/README.md)
明确自由流时间原单位为 0.01 小时，因此现在执行
`free_flow_time = 0.6 * source_free_flow_time`。例如源值 6 对应 3.6 分钟。
源长度是任意设为与原时间相同的数值，现在保留为 `source_length`，不赋予公里单位，
也不用于额度计量。路段时间固定，不随流量变化。

OD 源表合计 360600，源表数值是原始日车辆流量的 0.1 倍；不能当作月度旅客人数。
本实验仅用这些数值的比值构造权重：
\(w_{od,t}=s_tq_{od}/\sum q_{od}\)。容量也保留源表标度，仅以源值 10000 为模式划分阈值：
不低于阈值的 28 条有向路段为 trunk，其余 48 条为 feeder；容量不进入供给或拥堵约束。
输出利润不乘 360600；如需市场总利润，须另给与上述人口份额一致的实际人数。

## 旅客与经济参数

| 参数 | 类型 1 | 类型 2 | 单位 |
| --- | ---: | ---: | --- |
| 每 OD 内占比 | 0.45 | 0.55 | 无量纲 |
| 时间价值 | 0.18 | 0.32 | USD/人·分钟 |
| 等价每小时时间价值 | 10.8 | 19.2 | USD/人·小时 |
| trunk 偏好成本 | 0.02 | 0.08 | USD/路段通行次 |
| feeder 偏好成本 | 0.10 | 0.03 | USD/路段通行次 |
| 月度出行次数 | Uniform(8,20) | Triangular(20,32,44) | 次/人·月 |
| 平均月度出行次数 | 14 | 32 | 次/人·月 |

| 模式 | PAYG 费率 | 单位额度供给成本 |
| --- | ---: | ---: |
| trunk | 0.45 USD/路段通行次 | 0.05 USD/路段通行次 |
| feeder | 0.75 USD/路段通行次 | 0.08 USD/路段通行次 |

例如 \(K_b=0.05\varepsilon_{b,\mathrm{trunk}}+0.08\varepsilon_{b,\mathrm{feeder}}\)
的单位为 USD/人·月，和月费 \(C_b\) 相减得到套餐 margin。
当前仍运行线性供给成本特例；接口本身支持其他成本形状。
PAYG 平台 margin 为零，超额 PAYG 支出进入旅客成本，不另加到平台目标。

## 初值与优化约束

| 选项 | 月费（USD/人·月） | trunk 额度（路段次/人·月） | feeder 额度（路段次/人·月） |
| --- | ---: | ---: | ---: |
| PAYG | 0 | 0 | 0 |
| 套餐 1 | 20 | 32 | 16 |
| 套餐 2 | 40 | 80 | 48 |

随机初值默认 30 个、种子 `20260901`：

- 两个月费分别抽自 U[4,64)，排序，单位 USD/人·月。
- 套餐 1 的两种额度分别抽自 U[0,48)，单位路段次/人·月。
- 套餐 2 在套餐 1 的每个额度上增加 U[0,72)，单位路段次/人·月。
- 仅接受真实 optimistic 利润大于 `1e-9 USD/人·月` 的菜单。
- 最多尝试 `100 * starts` 个候选，失败时报错，不补入全 PAYG 初值。

这些采样范围不是优化边界。上层有 6 个连续变量，要求价格和额度非负、两个收费套餐
价格递增及区域选择约束；没有价格/额度上界，没有强制套餐额度递增。

## 求解设置与可复现性

SLSQP：每次最多 2000 次迭代，`ftol=1e-9`，失败后重启及回退 trust-constr；
每个初值最多 30 个区域。区域可行性容差 `1e-7`，独立归一化 KKT 容差 `1e-5`。
选择成本差、利润容差分别为 `1e-9 USD/人·月`；求解后有效选择/分离容差与 NLP
可行性容差协调为 `1e-7`。同菜单比较使用坐标绝对容差 `1e-7` 和无量纲相对容差
`1e-6`，价格坐标按 USD/人·月、额度坐标按路段次/人·月解释绝对容差。
普通 tie 和 double tie 的流程见[边界搜索](boundary_assignment_search.md)。

```bash
maas-bundle example sioux-falls
maas-bundle multistart sioux-falls --starts 30 --seed 20260901
```

Python 调用可用 `dataclasses.replace(DEFAULT_SIOUX_FALLS_CONFIG, ...)` 创建配置，传入
`build_sioux_falls_problem(config=...)`、`run_sioux_falls_example(config=...)` 或
`run_sioux_falls_multistart(..., config=...)`。oracle 缓存键包含配置，避免修改时间价值、
费率或模式划分后误用旧极点。缓存仅在当前进程内复用。

本次重新设定月度出行频次、月费和额度（这些数值为旧设置的 4 倍），同时纠正源时间
到分钟的换算；旧设置没有明确计费周期，不能将此次调整称为已知周数据到月数据的换算。
此前利润 `3.27138465` 属于旧参数配置，不能作为当前美元月度实验结果。
